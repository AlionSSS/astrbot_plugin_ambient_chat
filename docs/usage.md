# 使用与配置

本文件是「聊天氛围组」的完整配置手册。README 只保留最短上手路径，这里覆盖每个参数的取值范围、默认值与运行期行为。

## 开关层级

插件里有三层互不相同的开关，作用范围由外到内：

| 层级 | 位置 | 关闭后的效果 |
| --- | --- | --- |
| 插件开关 | AstrBot「插件管理」 | 插件不再加载，控制台页面与接口一起失效 |
| 自主发言总开关 | 插件配置页 `enabled` | 只停调度，规则、绑定与页面都保留，可继续编辑 |
| 绑定启停 | 「运行管理」页 | 只影响那一条绑定，其他绑定照常运行 |

## 插件配置页

插件配置页只有一个总开关：

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | 自主发言总开关，关闭后仅暂停调度（规则与页面保留） |

运行参数移到控制台的「更多设置」页，保存在 `settings.json` 的 `settings` 段，保存后立即生效。

## 更多设置

### 发言节奏

| 设置项 | 字段 | 范围 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 同时进行的发言数上限 | `concurrency` | 1~5 | `1` | 名额覆盖意向判断、生成、发送及历史记录；调低上限不打断已有执行 |
| 两次发言之间的最小间隔（秒） | `send_interval_seconds` | 0~30 | `2.0` | 约束实际发送开始时刻，允许不同会话并行生成 |

### 上下文缓冲

| 设置项 | 字段 | 范围 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 每个会话保留的近期消息条数 | `buffer_size` | 10~1000 | `100` | 文本在内存、图片落盘，插件重启后清空；覆盖「注入最近对话条数」所需即可，不建议设得过多 |
| 不进入缓冲区的用户 ID | `buffer_ignored_sender_ids` | 最多 200 个 | 空 | 逗号分隔；这些用户的消息不写入缓冲，启动预热的历史也会跳过，机器人自己的发言不受影响；保存后同时清掉缓冲里已有的这些人的消息 |
| 是否缓存图片 | `cache_images` | 开关 | 开启 | 开启后图片转存到磁盘，随消息淘汰删除，关闭时清空已缓存的图片；仅多模态模型可见 |
| 缓存图片最长边（像素） | `image_max_edge` | 320~2048 | `1280` | 落盘时长边超出则等比缩小；与核心的图片压缩上限默认值一致 |
| 缓存图片压缩质量 | `image_quality` | 40~95 | `80` | JPEG 重编码质量，越低越省磁盘、画质损失越明显 |

### 决策模型

自定义决策模型（SystemOne 兼容端点）最多 10 个，规则用 `custom:<id>` 引用；官方 AstrBot 判断提供商仍按 provider id 引用。每条包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 模型 ID，只能包含字母、数字、下划线与短横线 |
| `name` | 展示名称，留空时取模型 ID |
| `base_url` | 接口地址，需以 `http://` 或 `https://` 开头 |
| `model` | 模型 ID |
| `api_key` | 可选 |

### 调试

`decision_debug_enabled` 默认 `false`，在「更多设置 → 调试」勾选后保存启用。官方决策、自定义决策和模型测试均遵循此开关；记录包含完整请求与响应，可能包含人格、聊天内容和会话标识。

日志位于插件数据目录的 `decision_debug/`，最多保留最近 100 条 JSON 记录、总计 10 MiB，超限自动删除旧记录；单条超过 10 MiB 不保存。关闭后停止写入，在途请求也不再落盘，已有日志保留，可手动删除。旧版写入系统临时目录 `astrbot_ambient_debug/` 的文件不纳入新目录轮转，需自行清理。

## 规则参数

### 入口触发（可配置多条，任一命中即进入下一阶段）

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| `cron` | `expr` | crontab 表达式，分钟粒度重复 |
| `once` | `at` | 一次性时刻（ISO 8601）。允许保存过去的时刻，但会被标成「已过期」且永不触发 |
| `window` | `start` / `end` / `count` / `gap_minutes` / `days` | 每日在窗口内均匀随机取 `count` 次（1~20），任意两次至少间隔 `gap_minutes` 分钟；`days` 为生效星期（1~7，周一为 1，缺省每天）；**不支持跨天**，跨天请拆成两个窗口。窗口放不下时保存被拒绝 |
| `interval` | `every_minutes` / `jitter_percent` | 固定间隔，周期 1~1440 分钟，抖动比例 0~60（按周期百分比）；从绑定在进程内首次调度时刻起算，不按整点对齐 |

同一绑定的多次触发落在 60 秒内时合并成一次（一次性触发照常消耗，只是不再执行）。合并窗口从执行被接纳时开始，包含等待并发名额的时间；不以生成或发送完成时间为基准，多目标触发以首个接纳为准。全部目标忙碌或未获接纳时不刷新基准。

固定间隔的抖动按周期确定，重算时会保留因正向抖动而尚未到期的触发，并按实际时间选择最早候选；抖动超过 50% 时相邻周期可能换序。已经到期的时刻不再返回，也不集中补发过期触发。

### 拦截（按会话独立判断，任一命中即放弃该会话本次发言）

| 类型 | 字段 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `silence` | `windows[]` | 空 | 静默时段，每个窗口含 `start` / `end`（`HH:MM`），支持跨午夜（如 `23:00`~`09:00`） |
| `cooldown` | `minutes` | `5` | 自身活跃度冷却，1~1440 分钟 |
| `unread` | `min_count` | `10` | 自上一条 bot 发言以来该会话收到的消息条数下限，0~10000 |
| `unanswered` | `count` / `minutes` | `3` / `180` | 机器人在同一会话连续发言达到 `count` 条（1~100）且期间无人回应，则自最后一次发言起等待 `minutes` 分钟（1~`sys.maxsize`，填极大值等同永久等待）。一旦有人发言，计数清零、拦截解除 |

`unanswered` 的判定数据来自上下文缓冲，插件重启或绑定停止后重新计数。

`cooldown` 的最近自身发言时间与 `unread` 的未读累计独立于消息容量，消息淘汰或缓冲缩容不会丢失。机器人发言后未读归零；过滤用户 ID 会同时扣除其未读累计，包括已淘汰的消息。停止或重启会清空这些状态，启动时仅能从本次读到的预热历史重建；不会恢复未被读到的历史统计，时间未知的 bot 消息不能恢复冷却时间。

### 发言意向

| 字段 | 说明 |
| --- | --- |
| `mode` | `direct`（直接放行）或 `decision`（决策模型判定） |
| `decision_provider_id` | 决策模型引用：官方提供商 id，或「更多设置」里的 `custom:<id>`；留空回退到默认提供商 |
| `threshold` | 判定阈值，0~1，默认 `0.7`；「是否感兴趣」与「是否想开新话题」共用 |

判定顺序：感兴趣 → 接话；否则想开新话题 → 发起新话题；两者皆否则放弃。两个判定值都会写进「运行管理」里该会话的结果（如 `感兴趣（感兴趣 0.53 / 新话题 0.21）`）。**决策失败一律放弃**（fail-closed），只记 WARNING。

### 其他规则字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `chat_provider_id` | 空 | 对话模型；留空回退到默认（第一个）提供商 |
| `context_turns` | `20` | 注入给模型的最近消息**条数**（1~200，字段名为历史兼容保留，语义不是对话轮次） |
| `inject_persona` | `true` | 是否把会话当前人格注入给决策模型与对话模型，两者同开同关 |
| `updated_at` | 空 | 最近一次保存内容的时刻，只用于 WebUI 排序，不影响运行 |

规则本身**没有启停状态**：能被哪些机器人应用、在哪些会话里生效，完全由绑定决定。

## 绑定参数

| 字段 | 说明 |
| --- | --- |
| `platform_id` | 机器人应用，即 UMO 前缀；目标会话的平台前缀必须等于它 |
| `rule_id` | 一条绑定只带一条规则；要给同一个号再加规则，就再建一条绑定 |
| `name` | 绑定名称，可留空，后端兜底生成 `未命名-N`（取该机器人下第一个空位）；同一机器人内允许重名，不参与运行期判断 |
| `targets` | 目标会话 UMO 列表（`platform_id:message_type:session_id`） |
| `selection` | `mode` 为 `all`（按列表顺序）或 `random`（随机挑 `count` 个，1~50，不小于目标数时退化为全部），按挑选顺序逐个处理 |
| `enabled` | 启停状态，只能由「运行管理」页写入；新建绑定落在停止态 |

约束：

- 同一机器人应用下可以有**多条绑定**；同一条规则也可在同一机器人应用上出现多次（典型用法：同规则的「随机挑 3 个」与「全部」用于不同的会话集合）。
- **目标会话在机器人应用内唯一**：同一个 UMO 最多出现在该机器人的一条绑定里（含已停止的），保存时校验并点名占用方。
- 规则被绑定时**不能删除**：删除未被引用的规则才生效，且不影响任何绑定；删除或停止绑定都不会改动规则。
- **不能主动发消息的平台**（当前只有 WebChat）：照常显示在左栏、历史绑定可编辑可删除，但不给「新增绑定」；该校验只在前端。

## 运行期行为

定时触发与「手动触发一次」共用执行管理，同一会话忙碌时新触发立即跳过、不排队。

- **手动触发一次**：「运行管理」页对单个会话的按钮，跳过入口触发、挑选策略与 60 秒合并，但仍走拦截与意向判断，可能最终不发言；要求绑定处于启动态，确认后才真正发送，且不消耗一次性触发。
- **并发与节奏**：全局并发名额从意向判断前保持到发送及历史记录结束；调低并发让已有执行完成，新执行等待。最小间隔约束实际发送开始时刻，生成可并行；失败或结果未知的发送尝试也消耗间隔。
- **停止绑定**：取消等待、判断或生成；已经开始发送则等待结果与记录收尾，完成后清空缓冲。停止返回后不会再发起发送。
- **启动预热**：启动时先读取历史填充缓冲，期间不能重复启动，但可点击「取消启动」。预热期间保存或删除绑定、修改关联规则的实际内容会撤销旧启动，修改后需重新启动。
- **运行中的绑定只读**：可以查看，但必须先停止才能保存修改或删除（后端同样拒绝）。
- **发送超时**：发送最多等待 60 秒，超时显示「发送结果未知」且不自动重发（平台仍可能迟到送达）；确认发送后的历史记录整体最多 10 秒，失败显示「已发送，但会话历史记录失败」。
- **配置变更**：保存规则只使受影响的待发送执行失效，无关绑定继续运行；间隔变化从下一次尚未开始的发送生效。

「运行管理」页的「缓冲区」按钮可以打开该会话的只读快照，列出当前缓冲里的最近消息（与注入模型的那份文本一致）；停止的绑定会提示缓冲已清空。

## 上下文缓冲与图片缓存

上下文缓冲是插件按目标会话自行维护的最近消息环形缓冲，决策与生成都读它。

- **启动预热**在三个时机执行：插件加载（含热重载）、绑定从停止变启动、总开关从关变开。群聊读核心的平台消息历史（依赖核心的群消息持久化开关），私聊读核心的 LLM 会话历史（只含走过 LLM 的消息）。**停止绑定会清空该绑定目标会话的缓冲**（含已缓存图片），下次启动重新预热；触发路径不查库。
- **图片缓存默认开启**，可在「更多设置 → 上下文缓冲」里关闭；首次进入设置页时会提示一次「建议开启」，提示状态记在 `settings.cache_images_advice_seen`，跨会话不再重复；之后每次把「是否缓存图片」勾选成开启，都会弹窗说明磁盘占用、画质损失与 token 消耗，取消或 Esc 关闭会回退勾选。关闭时清空已缓存的图片。开启后文本留在内存，图片字节写到 `data/plugin_data/astrbot_plugin_ambient_chat/media/`，随消息淘汰释放。
- **视觉输入**：生成时取最近 8 张缓存图片随请求发送。每次读取 AstrBot 供应商的 `modalities` 配置；非空列表中不含 `image` 时直接走纯文本。空列表保留核心迁移兼容语义，字段缺失或无法读取时保留尝试带图的行为。带图请求失败后仅本次去图重试，不从网络、额度或其他请求错误推断永久能力限制；配置修改后下次请求即按新配置处理。
- **限额**：单条消息最多 4 张；单张源图 ≤ 64 MiB 且 ≤ 50 MP，超出直接丢弃（消息只留文本占位）；每个会话缓冲中的图片 ≤ 64 MiB。
- **压缩**：落盘时按「图片最长边 / 压缩质量」重编码（允许损失画质）。长边超出则等比缩小，非透明图重编码为 JPEG；带透明通道的图优先保留 PNG，只有当 PNG 仍大于 1 MiB 时才铺白底转 JPEG；透明通道形同虚设（99.5% 以上像素不透明）的图直接按 JPEG 存。小于 512 KiB 且长边未超限的图、以及压缩后反而更大的图，保留原始字节。动图只保留首帧。
- **生命周期**：正在生成使用的图片保留到该次模型请求结束再删除；停止绑定或关闭图片缓存会立即撤销旧转存，已开始的压缩在后台收尾并回收产物，重新开启不会挂回旧图片。插件卸载会等待写盘和图片借用结束后清理目录，这期间实际磁盘占用可能短暂高于缓冲统计值。

## 注入给模型的内容

自主发言不经过核心管线，核心的 `datetime_system_prompt` 不生效，因此插件自己补时间与会话上下文，避免「隔夜的话当连续对话」「把私聊当群聊」这类错位。

请求结构固定为：

- **system 提示**：只有会话当前生效人格（由规则的「向模型注入人格」控制，关闭时为空）。
- **用户消息**：最近 N 条消息 + 时间与会话信息 + 本次发言提示（提示在最后）。

时间与会话信息包含当前日期时间与星期、距最后一条消息多久、以及会话类型（私聊 / 群聊）。历史记录块用 `<recent_conversation>` 包裹并明确标注「不是用户刚发来的消息」，避免模型把历史当成新收到的消息。

## 数据文件

配置保存在 `data/plugin_data/astrbot_plugin_ambient_chat/settings.json`，随 AstrBot 备份一起迁移。提交由 `RuleStore` 统一管理：写入失败时原有配置保持生效。

  "settings": {
    "concurrency": 1,
    "send_interval_seconds": 2.0,
    "buffer_size": 100,
    "buffer_ignored_sender_ids": [],
    "cache_images": true,
    "image_max_edge": 1280,
    "image_quality": 80,
    "decision_debug_enabled": false,
    "decision_models": [
      {
        "id": "judge",
        "name": "夜话判断",
        "base_url": "https://example.com/systemone",
        "model": "systemone-v1",
        "api_key": ""
      }
    ],
    "cache_images_advice_seen": false
  },
  "rules": [
    {
      "id": "r_7f3a",
      "name": "夜话",
      "triggers": [
        { "type": "cron", "expr": "*/10 * * * *" },
        { "type": "once", "at": "2026-11-02T01:18:00+08:00" },
