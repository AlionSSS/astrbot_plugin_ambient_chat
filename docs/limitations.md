# 已知限制

本文件记录当前版本明确的边界与取舍。配置项取值范围见 [usage.md](usage.md)，设计背景见 [adr/](adr/)。

## 生成与投递

- 自主发言由插件直接调用对话模型生成，不经过核心管线：提示语不会写入会话历史，也不再受 `ignore_bot_self_message` 影响；发送成功后这条发言会作为 `assistant` 追加进当前 LLM 会话，用户回复时模型能感知到。**没有当前 LLM 会话时（用户还没和 bot 聊过）直接跳过本次发言**，不新建会话。代价是表情包、记忆、装饰、TTS、工具调用等依赖管线的能力不参与，模型只看到插件自建的上下文。
- 发送走 `context.send_message`：找不到对应平台实例时只记 WARNING，不会重试；平台连接异常会在触发结果里显示为「投递失败」。
- 多个平台实例配置同一个 `ws_reverse_port` 时只有最先启动的那个能收发消息；「氛围组绑定」左栏的机器人清单会把探测不到的实例标成「未连接」，选错实例会导致触发时无法投递。
- 生成的请求链路只依赖 `context.llm_generate()` / `context.send_message()` / `get_current_chat_provider_id()` 这几个公共接口，升级 AstrBot 大版本后仍需回归验证。

## 消息与上下文

- 为了拿到全量群消息，插件注册了 ALL 类型监听并配了自定义过滤器：只有**已启动且预热就绪的绑定**覆盖的会话才会被唤醒并写入缓冲；普通 bot 回复也检查同一目标归属（最多跟踪 500 个会话），未绑定或已停止的会话完全不受影响。
- 「最近 N 条消息」优先用内存缓冲。**启动预热**在三个时机执行：插件加载（含热重载）、绑定从停止变启动、总开关从关变开。群聊读核心的平台消息历史（依赖核心的群消息持久化开关），私聊读核心的 LLM 会话历史（只含走过 LLM 的消息，且只有最后一条有准确时间）。**停止绑定会清空该绑定目标会话的缓冲**（含已缓存图片与语音），下次启动重新预热，因此停止期间的消息要靠核心历史补回来。
- 「加载该机器人的最近会话」依赖核心的会话表（`conversation_manager`），只有产生过 LLM 对话的会话才会出现在建议列表里，其余请手动粘贴 UMO。
- 「新增绑定」只能针对左栏已有的机器人应用：适配器还没被 AstrBot 加载出来时它不在列表里，建不了绑定（等它出现再建即可，绑上发不出消息）。
- 一对多且选择随机时，被挑中的多个会话默认串行处理（「更多设置」里的并发上限默认 1，可调至 5），一次触发可能持续数秒到数十秒；随机挑选不带记忆，短期可能重复挑中同一批会话（关注度/评分机制尚未实现）。

## 媒体缓存（图片与语音）

- 生成时取最近 8 张缓存图片作为视觉输入；bot 自身发送的图片不转存；决策模型只能看到 `type: "image"` 条目，看不到图片内容。
- 缓存图片是有损的：落盘时按「图片最长边 / 压缩质量」重编码，动图只保留首帧，带透明通道的大图会铺白底转 JPEG。
- 语音缓存默认关闭，开启后生成时取最近 2 段语音作为音频输入；bot 自身发送的语音不转存；决策模型只能看到 `type: "audio"` 条目，看不到也听不到语音内容。
- 语音不压缩、不转码，落盘格式取决于平台（silk/amr 等），由核心在发请求时转成 wav；单段 ≤ 16 MiB。
- 限额与生命周期细节见 [usage.md](usage.md#上下文缓冲与媒体缓存)。

## 数据与兼容

- 当前 `schema_version` 为 `6`。读盘没有版本上界守卫，把新版 `settings.json` 拿回旧版插件时，旧版按 `platform_id` 去重，会**静默丢弃**同一机器人应用除第一条以外的绑定。
- 仅支持 `aiocqhttp`（`support_platforms`），其他平台未验证。
- 规则、绑定与更多设置保存在插件数据目录，删除插件数据目录等于清空全部配置与图片、语音缓存。
